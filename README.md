# マルチ移動手段ルート検索

区間ごとに移動手段(自動車/徒歩/自転車/公共交通)を選び、**1回の検索**で全行程の経路・距離・移動手段別の時間・合計時間を表示します。経路はGoogle Maps PlatformのRoutes APIで取得します。サーバーを持たない静的なWebアプリで、GitHub Pagesで公開してiPhoneから使えます。

## 使い方

1. 画面上部の「APIキー」にキーを入力(そのブラウザの中にだけ保存されます)。
2. 地点を順に入力し、区間ごとに移動手段を選ぶ。経由地には滞在時間(分)を入れられます。「サンプル」で東京の例(上野駅→徒歩→上野恩賜公園で30分→公共交通→東京駅→徒歩→皇居外苑)が入ります。
3. 「いまから出発/出発時刻/到着時刻」を選び、「ルート検索」を押す。移動手段別の時間と合計、各地点の発着時刻、地図が出ます。
4. よく使うルートは「お気に入り」に名前をつけて保存。お気に入りはそのブラウザの中にだけ保存されます。別の端末へは「共有」でコピーしたリンクを開くと追加されます(リンクに地点が含まれるので、渡す相手に注意)。
5. 「現在の区間」のボタンで、iPhoneのGoogleマップアプリの車ナビ(CarPlayに接続中なら車の画面にも表示)や徒歩ナビを開始。降車したら「到着・降車 → 次へ」で次の区間へ。

## APIキーの用意

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作り、請求先を紐づける。
2. **Routes API**, **Places API (New)**, **Maps JavaScript API** を有効化。
3. キーを1つ作り、API制限を上の3つだけにし、**HTTPリファラ制限**に公開URL(例: `https://ユーザー名.github.io/*`)と、ローカル確認用に `http://localhost:5173/*` を指定。
4. 予算アラート(お支払い → 予算とアラート)と、各APIの1日あたり上限(割り当て)を設定。

キーはブラウザで使う性質上、ページを開いた人に見えます。リファラ制限とAPI制限が防御の要で、他人にキーを入力させたり、URLと一緒に配ったりしないでください。キーはコードにもリポジトリにも含まれません。

## 料金(2026-10-29時点の調査。必ず公式で再確認)

- 月間無料利用枠方式。調査では Compute Routes Essentials は月10,000件まで無料、Proの無料枠は5,000件という記載を確認しましたが、キャッシュされた検索結果での確認で**未検証**です。最新は [料金ページ](https://developers.google.com/maps/billing-and-pricing/pricing) と [Routes API 課金](https://developers.google.com/maps/documentation/routes/usage-and-billing?hl=ja) を参照。
- 自動車区間は渋滞考慮(`TRAFFIC_AWARE`)のため、上位SKU(Pro)の対象になる可能性があります。
- **1回の検索のリクエスト数 = 区間数**。入力中のオートコンプリートでも別途リクエストが発生します。無料で使えるとは断定できません。

- 車区間は渋滞考慮(TRAFFIC_AWARE)のため Compute Routes Pro(月5,000回無料、以降 1,000回あたり$10〜)。訪問順の最適化も Pro。
- 高速代をオンにすると、車区間は Compute Routes Enterprise(月1,000回無料、以降 1,000回あたり$15〜)。
- 営業時間をオンにすると、地点ごとに Place Details Enterprise(月1,000回無料、以降 1,000回あたり$20〜)。同じ地点は1週間再取得しません。

### 無料のまま使うために(必ず設定)

アプリは、このブラウザで今月使った回数を数え、無料枠の約8割で自動的に止めます(⚙ 設定で回数を確認できます)。ただし別の端末の分は合算できないので、Google Cloud 側でも1日の上限を設定してください。上限を超えたリクエストはエラーになるだけで、課金されません。

1. Google Cloud コンソール →「APIとサービス」→ 対象のAPI(Routes API / Places API (New) / Maps JavaScript API)を開く
2. 「割り当てとシステム上限(Quotas)」で、1日あたりのリクエスト数の上限を下げる(目安: Routes API 150/日、Places API 300/日、Maps JavaScript API 300/日。月30日で無料枠に収まる値)
3. 「お支払い」→「予算とアラート」で予算を1円などにしてメール通知を受ける(通知のみで止まりはしないため、2と併用)

高速代・営業時間の自動チェックは無料枠が月1,000回と小さいため、オフのままでも各区間の「Googleマップ」リンクや「営業時間を見る」で確認できます(Googleマップのページを開くだけなのでAPIの料金はかかりません)。

## GitHub Pages で公開

1. GitHubでリポジトリを作成(無料プランのPagesは公開リポジトリ)。
2. このフォルダをプッシュ(`main` ブランチ)。
3. リポジトリの Settings → Pages → Source を **GitHub Actions** にする。
4. `.github/workflows/pages.yml` が型チェック後にテストとビルドを行い、公開します。公開URLは `https://ユーザー名.github.io/リポジトリ名/`。
5. そのURLをAPIキーのリファラ制限に追加。

5-2. 公共交通(電車・バス)は Transit API(https://api.transit.ls8h.com/ 非公式・無料・キー不要)で自動検索します。各事業者の公開データ(GTFS・ODPT等)の時刻表に基づき、前の区間の到着時刻以降に乗れる便を探して、発車時刻・待ち時間・乗換回数・運賃を表示します(「乗換の詳細」をタップで路線・駅ごとの時刻)。地点は Transit API の地点検索で解決し、Googleの座標は渡しません。見つからない・通信できないときは「自動検索できないときの所要◯分」の手入力に戻ります。⚙ 設定でオフにできます。実際の運行と異なる場合があります。
6. 新幹線・飛行機は移動手段「新幹線・飛行機」を選び、便名(任意)と発・着の時刻を入力。APIは使わず、その時刻で計算します。乗る駅・空港には発車時刻まで待つ扱いになり、間に合わなければ「遅れ」と表示します。距離は出ません。地図には両端を結ぶ破線を引きます(前後の区間がある場合のみ)。
7. 「⚙ 設定」で燃費(km/L)とガソリン単価(円/L)を入れると、車区間のガソリン代の目安(距離÷燃費×単価、高速代は含まない)を表示します。
8. 要注意の区間(乗り継ぎ余裕10分未満・新幹線/飛行機の発車まで15分未満・遅れ・徒歩20分以上・自転車40分以上・2時間以上の連続運転)は黄色の枠と理由で強調します。

9. 複数日の旅程: 経由地の「🏨 宿泊」を押すと、そこで1泊して翌日の指定時刻(初期値9:00)に出発します。以降の時刻指定は翌日の時刻として扱います。
10. 当日の再計算: 区間を進めている途中で「📍 現在地から再計算」を押すと、現在地から残りの区間を今の時刻で取り直します(位置情報の許可が必要)。
11. 予定の共有(閲覧専用): 検索結果の「📤 予定を共有」で、時刻・所要・距離を入れたリンクを作ります。開いた人はAPIキーなしで予定表を見られます(編集はできません。地点名がリンクに含まれます)。iPhoneでは共有シートが開きます。

12. 訪問順の最適化: 経由地が2つ以上あれば「🔀 訪問順を最適化」で、車の所要が短くなる順に経由地を並べ替えます(出発地・目的地は固定。新幹線・宿泊・時刻指定のある経由地があると使えません)。
13. カレンダー: 「📅 カレンダー」で .ics ファイルを読み込み、日付を選ぶと、その日の場所つき予定が経由地になります(到着時刻=開始、滞在=予定の長さ、目的地=出発地)。ファイルはブラウザの中で読むだけで、どこにも送りません。Googleカレンダーは「設定 → インポート/エクスポート → エクスポート」で .ics を書き出せます。
14. 高速代・営業時間(⚙ 設定でオンにしたときだけ): 車区間の高速代(Googleが金額を返せない区間は「金額不明」)と、候補から選んだ立ち寄り先の営業時間外・滞在中の閉店を警告します。料金区分が上がります(下の料金を参照)。

## Claude(Cowork・ブラウザ操作)から使う

画面の入力欄・ボタンには名前(aria-label)を付けてあり、ブラウザ操作で「地点A 出発地」「A→Bの移動手段: 自動車」などとして指定できます。
地点を一度に入れたいときは、URLの `#plan=` にJSONを付けて開くと入力欄に入ります(保存はされません。検索は「START」を押す)。

```
https://sugoikashikoi.github.io/route-app/#plan={"stops":[{"text":"東京駅","modeToNext":"FIXED","fixedName":"のぞみ1号","fixedDepart":"10:00","fixedArrive":"12:30"},{"text":"新大阪駅","modeToNext":"WALK"},{"text":"大阪城公園"}]}
```

`modeToNext` は DRIVE/WALK/BICYCLE/TRANSIT/FIXED。ほかに `dwellMin`(滞在分)、`overnight`(宿泊、true)、`arriveBy`・`departAt`("HH:MM")も指定できます。APIキーは開いたブラウザに保存済みのものを使います。

## 動作確認の状況(正直な記録)

- 確認済み: 型チェック、ビルド、単体テスト(**モックデータによる**レスポンス変換・時間整形・URL生成のテスト)。
- **未確認**: 実際のGoogle APIへの呼び出し(Routes API/Places APIがブラウザから直接呼べること、CORS、地図描画、オートコンプリート)。開発環境にAPIキーがなかったためです。キー設定後に「サンプル」で確認してください。
- iPhone・CarPlayでの実機動作も未確認です。ナビ開始リンクはGoogle公式のMaps URLの仕様に基づきます。出発地が現在地付近でない場合、ナビではなく経路プレビューになります。
- 日本では自転車・公共交通が経路なしになる事例が報告されています。その場合は区間ごとに「経路が見つかりませんでした」と表示し、結果は捏造しません。
