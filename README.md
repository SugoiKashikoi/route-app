# マルチ移動手段ルート検索

区間ごとに移動手段(自動車/徒歩/自転車/公共交通)を選び、**1回の検索**で全行程の経路・距離・移動手段別の時間・合計時間を表示します。経路はGoogle Maps PlatformのRoutes APIで取得します。サーバーを持たない静的なWebアプリで、GitHub Pagesで公開してiPhoneから使えます。

## 使い方

1. 画面上部の「APIキー」にキーを入力(そのブラウザの中にだけ保存されます)。
2. 地点を順に入力し、区間ごとに移動手段を選ぶ。経由地には滞在時間(分)を入れられます。「サンプル」で東京の例(上野駅→徒歩→上野恩賜公園で30分→公共交通→東京駅→徒歩→皇居外苑)が入ります。
3. 「いまから出発/出発時刻/到着時刻」を選び、「ルート検索」を押す。移動手段別の時間と合計、各地点の発着時刻、地図が出ます。
4. よく使うルートは「お気に入り」に名前をつけて保存。お気に入りはそのブラウザの中にだけ保存されます。別の端末へは「共有」でコピーしたリンクを開くと追加されます(リンクに地点が含まれるので、渡す相手に注意)。
5. 「現在の区間」のボタンで、iPhoneのGoogleマップアプリの車ナビ(CarPlayに接続中なら車の画面にも表示)や徒歩ナビを開始。降車したら「到着・降車 → 次へ」で次の区間へ。

## APIキーの用意

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作り、請求先を紐づける。
2. **Routes API**, **Places API (New)**, **Maps JavaScript API** を有効化。
3. キーを1つ作り、API制限を上の3つだけにし、**HTTPリファラ制限**に公開URL(例: `https://ユーザー名.github.io/*`)と、ローカル確認用に `http://localhost:5173/*` を指定。
4. 予算アラート(お支払い → 予算とアラート)と、各APIの1日あたり上限(割り当て)を設定。

キーはブラウザで使う性質上、ページを開いた人に見えます。リファラ制限とAPI制限が防御の要で、他人にキーを入力させたり、URLと一緒に配ったりしないでください。キーはコードにもリポジトリにも含まれません。

## 料金(2026-10-29時点の調査。必ず公式で再確認)

- 月間無料利用枠方式。調査では Compute Routes Essentials は月10,000件まで無料、Proの無料枠は5,000件という記載を確認しましたが、キャッシュされた検索結果での確認で**未検証**です。最新は [料金ページ](https://developers.google.com/maps/billing-and-pricing/pricing) と [Routes API 課金](https://developers.google.com/maps/documentation/routes/usage-and-billing?hl=ja) を参照。
- 自動車区間は渋滞考慮(`TRAFFIC_AWARE`)のため、上位SKU(Pro)の対象になる可能性があります。
- **1回の検索のリクエスト数 = 区間数**。入力中のオートコンプリートでも別途リクエストが発生します。無料で使えるとは断定できません。

## 開発

```bash
npm install
npm run dev       # http://localhost:5173
npm run typecheck
npm test
npm run build
```

## GitHub Pages で公開

1. GitHubでリポジトリを作成(無料プランのPagesは公開リポジトリ)。
2. このフォルダをプッシュ(`main` ブランチ)。
3. リポジトリの Settings → Pages → Source を **GitHub Actions** にする。
4. `.github/workflows/pages.yml` が型チェック後にテストとビルドを行い、公開します。公開URLは `https://ユーザー名.github.io/リポジトリ名/`。
5. そのURLをAPIキーのリファラ制限に追加。

## 動作確認の状況(正直な記録)

- 確認済み: 型チェック、ビルド、単体テスト(**モックデータによる**レスポンス変換・時間整形・URL生成のテスト)。
- **未確認**: 実際のGoogle APIへの呼び出し(Routes API/Places APIがブラウザから直接呼べること、CORS、地図描画、オートコンプリート)。開発環境にAPIキーがなかったためです。キー設定後に「サンプル」で確認してください。
- iPhone・CarPlayでの実機動作も未確認です。ナビ開始リンクはGoogle公式のMaps URLの仕様に基づきます。出発地が現在地付近でない場合、ナビではなく経路プレビューになります。
- 日本では自転車・公共交通が経路なしになる事例が報告されています。その場合は区間ごとに「経路が見つかりませんでした」と表示し、結果は捏造しません。
